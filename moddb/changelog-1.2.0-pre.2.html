New

  • Hitches outside the render stages now have a name. Every server packet that is not chunk data runs as a main-thread task, and a burst of them used to show up as an unnamed lump in the frame. The HUD and .komet report now name the packet type behind it (readpacket33=EntityLoaded rather than "somewhere outside"), and that drain runs under a per-frame budget, so a burst is spread over a few frames instead of stopping one dead.
  • World joins hitch less. The client used to build every entity the server sent in a single frame. Entities are now finished under a per-frame budget, nearest one first — a distant chicken appears a few frames later, which nobody can see, instead of the join stuttering.
  • Distant creatures animate less often. An entity whose shadow is the only thing on screen animates every third frame, one beyond 48 blocks every second frame, each time with the skipped time folded in — animation runs at the same speed, it is just sampled less. The own player and anything near you are untouched.
  • The HUD speaks German. The F7 overlay and the .komet chat replies follow the game language; English and German ship with the mod. Logs, reports and hitch lines stay English on purpose — they end up in bug reports and have to be readable by whoever helps you.
  • GPU time per render stage, next to the CPU time that was already there, plus the driver's own busy figure where the system exposes it. Together they answer "CPU-bound or GPU-bound?" without guessing.
  • The mod notices when another mod patches the same engine method and says so once, with a severity and a reason — including the case where Komet's own replacement quietly makes the other mod's patch do nothing. It also fingerprints the engine at world start, so a game update that changed a patched method is named instead of silently misbehaving. .komet conflicts lists it.
  • Server-side sync tuning for the integrated server (singleplayer): position updates thin out with distance, entity tracking gets a hysteresis band instead of flapping at the boundary, and attribute paths whose bytes did not change are not sent. Every rule is individually switchable.
  • More diagnostics: per-listener game tick profiling, allocation sampling by type, block packet sources, minimap upload budget and a direct upload path.

Fixed

  • Crash on joining a world (NullReferenceException in WeatherSystemClient, reported against pre.2). The new task budget could spread the join backlog over several frames, which let an already-registered renderer draw before the packet that initialises it had run. The budget now starts only once the world is finalised: everything a join queues runs in the frame it arrives, exactly like vanilla.
  • Budgets could stop for good instead of falling back. The entity tesselation and entity loading budgets reopen their window on the frame boundary and nowhere else. If that signal was missing, every further shape was skipped — permanently, for every animated creature — and held entities never loaded. Both now detect the missing signal and run vanilla instead, and the HUD counts it when it happens.
  • Measurement errors on engine methods that exist more than once, GPU timing and GPU load, GC and allocation statistics while the HUD is closed, and mesh pool allocations are now booked correctly.
  • Large hitches in the 2D stage are attributed to the dialog that caused them.
  • No more false hitch reports while the pause menu is open — the game is standing still, that is not a stutter.
  • Shadow map quality no longer overshoots on weak GPUs, and the CPU thread budget behaves on machines with few cores.
  • The misleading thread priority message on Linux is gone.

Changed

  • Config layout is now version 11 (20 new settings since 1.1.0). An existing komet.json is backed up next to itself and regenerated with defaults — re-apply your custom values afterwards.
  • Minimum game version stays 1.22.0. Built and verified against 1.22.7; on other 1.22.x builds any patch whose engine code changed logs a warning and switches itself off individually.

Internals

  • Release builds are reproducible: the same commit produces the same bytes, so the checksum below can be recomputed by anyone rather than merely trusted.
  • Every build now runs on GitHub Actions — both mods built, the full patch and behaviour suite executed against the real game assemblies, and the packaged zips attached to the run.

Verify your download

SHA-256 of the files on this page:

{{SHA256_KOMET}}  Komet_v1.2.0-pre.2.zip
{{SHA256_BASELINE}}  KometBaseline_v1.1.0.zip

Check it with sha256sum Komet_v1.2.0-pre.2.zip (Linux) or Get-FileHash Komet_v1.2.0-pre.2.zip (Windows PowerShell).

This page is not the only place that asserts them. github.com/xToast-dev/komet/releases carries the same numbers in the release notes and as .sha256 files next to the downloads, written by the build job rather than typed in by hand — so the checksum here and the checksum there have to agree, and neither was produced by whoever wrote this page.

Beyond comparing, you can rebuild it: check out {{COMMIT}} and run ./build.sh release, and every file inside the zip comes out byte for byte the same, Komet.dll included. The compiler is part of that — a different SDK patch level produces a different assembly — which is why the version is pinned in global.json rather than left to whichever machine builds. The checksum of the zip itself can still differ from the one above if your system compresses differently (zlib and zlib-ng do not produce identical streams from identical data); the file contents are what the build guarantees, and the checksum above belongs to the file published here.
