Changes since 1.2.0-pre.3. This release is mostly the GPU side of the frame. The first report that could measure it found the two shadow passes taking 86 % of a GPU-bound frame, and four of the five performance changes below come out of that one number.

Faster

  • The far shadow map is no longer redrawn on every frame while you move. It was already kept for a few frames and re-projected exactly — but a re-projection can only keep a kept map correctly positioned, not extend what it covers, so any camera movement of 15 centimetres forced a redraw. Walking, and especially flying, meant the saving never happened; it existed only while standing still. The map is now drawn a little wider than the shadow fade needs (16 blocks by default), which is exactly the room the camera needs to move without leaving it, and the redraw threshold rises to about 14 blocks in step. The far cascade then updates at its normal cadence whatever you are doing. It costs about 6 % coarser far shadows; ShadowFarBoxMargin sets the trade, .komet toggle shadowmargin flips it live.
  • The near shadow cascade gets a map of its own size. The engine allocated both cascades from one expression, so the near map was as large as the far one — over a hundred texels per block for a cascade covering the ~39 blocks around you, against the far map's fifteen. It is now 4096 px by default, which is a third of the fill rate for a difference nobody can see; near shadow edges come out about as crisp as vanilla draws them one quality step lower. .komet shadownear 3072 (or off) changes it while the game runs.
  • The solid parts of the shadow passes cost about half of what they did. They are now drawn with back-face culling (a closed block's back faces sit behind its front faces along the light ray too, so the depth map is identical) and with a shader that only writes depth instead of sampling the terrain texture for every fragment. Leaves and grass keep the engine's shader and cast from both sides, unchanged.
  • Far-detail stand-in geometry stays out of the shadow maps wherever the detailed version is already in them — the shadow pass had no distance rule at all and rasterised both. Decided per grid cell now, which is the granularity at which the rule actually fires.
  • A new creature type no longer costs a hitch the first time you see one. The engine builds an animation's frames on the main thread the moment it first plays; measured against the game's own shapes that is 12 ms for a rooster and 53 ms for a pig, always in the frame the animal comes into view. Those frames are now built on a worker while the entity is still being held back, and the main thread finds them ready.

New

  • A mod profiler with its own HUD (Shift+F7). Every measurement this mod made so far named a part of the engine — a render stage, a renderer, a tick listener. None of them answered the question somebody with forty mods installed actually asks, which is which of mine is it. The new overlay lists your mods by what they cost per frame, what they do (how many engine methods each one patches, how many block/item/entity classes it registers) and what each one cost during loading, client and integrated server separately. .komet mods prints the same thing as text for a bug report.
  • It also prints what it cannot see, rather than leaving it out: a Harmony patch runs inside the engine method it patches, so its time is booked to the engine — which is why the patch count sits next to the milliseconds — and block entity ticks, mod worker threads and GUI dialogs are not attributed at all.
  • A warning at world join when Optimum or OptiTime is present. Both replace the same engine code Komet does, each unaware of the other, and finding that out used to take a bisect. Now a dialog, a chat line and a log warning say so, and the report names the client in its header. Komet stays enabled — which side should win is your call.

Fixed

  • Crash on the first frame with the Optimum client build (MissingFieldException: ClientMain.MainThreadTasksLock, reported with Optimum v0.3.14). The fork declares that field with a different type, so the mod's binding no longer resolved. It is now read by name and locked the way its type demands; anything unexpected leaves that part vanilla with the usual "could not enable" line instead of taking the client down.
  • German clients filled their log with "Translation string format exception" — an error and a warning per HUD refresh for every label containing a number, thousands per session. The translation is now read as written and only formatted where the arguments actually exist.

Changed

  • Config layout is now version 15 (eight new settings since pre.3, five of them shadow-related). An existing komet.json is backed up next to itself and regenerated with defaults — re-apply your custom values afterwards.
  • Minimum game version stays 1.22.0. Built and verified against 1.22.7; on other 1.22.x builds any patch whose engine code changed logs a warning and switches itself off individually.

Internals

  • The shadow margin is not a tuning value that looked good in one scene: the covered volume is a sphere around the camera, so a sphere drawn 16 blocks wider provably contains what the shader will sample from anywhere within 16 blocks of where it was drawn. The check suite verifies that against the shader's own fade and edge constants, including the counter-test that the un-widened box really does fall short.
  • Release builds are still reproducible: the same commit produces the same bytes, so the checksum below can be recomputed rather than merely trusted.

Verify your download

SHA-256 of the files on this page:

{{SHA256_KOMET}}  Komet_v1.2.0-pre.4.zip
{{SHA256_BASELINE}}  KometBaseline_v1.1.0.zip

Check it with sha256sum Komet_v1.2.0-pre.4.zip (Linux) or Get-FileHash Komet_v1.2.0-pre.4.zip (Windows PowerShell).

This page is not the only place that asserts them. github.com/xToast-dev/komet/releases carries the same numbers in the release notes and as .sha256 files next to the downloads, written by the build job rather than typed in by hand — so the checksum here and the checksum there have to agree, and neither was produced by whoever wrote this page.

Beyond comparing, you can reproduce it: check out {{COMMIT}}, run ./build.sh release, and the file comes out with exactly the checksum above — on any machine. Two things make that work, and both cost something: the SDK version is pinned in global.json, because a different patch level produces a different assembly; and the zip is stored rather than compressed, because identical data does not give identical deflate streams across zlib implementations. The download is about 2.5x larger for it. That seemed the better trade for a mod whose whole point is that its claims can be checked.
